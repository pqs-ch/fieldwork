# Feeding project improvements back to Fieldwork

Follow these instructions when the project developer asks you to prepare feedback.

State the installed Fieldwork version once, using the application's lockfile. Then give one compact entry per concrete gap, defect or improvement encountered in project work:

- **UI requirement:** What the UI needed to support.
- **Fieldwork issue:** What was missing, broken, unsuitable or could work better in the pattern, element or instructions you used.
- **Implemented:** What you built or changed to meet the requirement.

Illustrative example:

> **UI requirement:** Filter owners by selecting multiple people.  
> **Fieldwork issue:** The example only demonstrated text filtering, so I copied that approach.  
> **Implemented:** A checkbox list in the column menu.

Keep each entry to a few sentences. Include missing capabilities, fixes and refinements to existing elements or patterns, based on actual project work. Omit general project descriptions and speculative proposals. Return the feedback to the developer for copying and pasting.
